3 Pendekatan Redesign Agent Pipeline

Pilih arsitektur yang paling sesuai untuk Bloomberg Terminal baru kamu

A

Incremental Replacement RECOMMENDED

Ganti 4 agen lama dengan 4 agen baru yang lebih powerful, pakai SSE pipeline yang sama. Tiap agen punya skillset yang jauh lebih dalam dari sebelumnya.

SEBELUM
Quant → angka dasar
Newsroom → scraping
Economist → macro
Critic → verdict
SESUDAH
DeepResearch → lap.keuangan + PDF
NewsIntelligence → sentiment AI
Strategy → entry/exit + signals
FinalVerdict → risk + rekomendasi

Pros

  • Cepat diimplementasi
  • UI existing tetap jalan
  • SSE pipeline tidak berubah

Cons

  • Struktur masih linear
  • Agen tidak bisa collaborate
B

Skills-Based Modular System

Inspired by Vibe-Trading: tiap agen punya skills library yang bisa di-call secara modular. Agen bisa invoke skill lain saat dibutuhkan.

SKILLS LIBRARY
📊 fetch_fundamentals
📰 sentiment_analysis
📈 technical_patterns
🔢 monte_carlo_sim
📄 parse_annual_report
⚡ generate_strategy

Pros

  • Sangat fleksibel
  • Skills reusable
  • Mudah di-extend

Cons

  • Kompleks dibangun
  • Lebih banyak API calls
C

Hierarchical DAG Pipeline

Inspired by Vibe-Trading's investment committee: ada Coordinator Agent yang mengatur agen-agen di bawahnya. Agen bisa jalan paralel berdasarkan dependency graph.

COORDINATOR
Research
⬇
Strategy
News
⬇
Risk
→ FinalReport

Pros

  • Paling powerful
  • True parallelism

Cons

  • Sangat kompleks
  • Sulit debug
  • Overkill untuk fase ini
💡 Rekomendasi saya: Mulai dengan A (Incremental) untuk Sub-project 1, lalu upgrade ke B (Skills) di Sub-project 2/3 saat fondasi sudah kuat.
